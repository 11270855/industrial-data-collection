## 四、PLC程序设计

### 4.1 PLC程序结构

本系统的PLC程序采用模块化设计，包含以下功能块：



#### 4.1.1 传送带控制功能块 (FB_ConveyorControl)

**功能说明**：控制传送带的启停、速度调节和功率计算

**输入变量**：
- `bStart`: BOOL - 启动命令
- `rSpeedSetpoint`: REAL - 速度设定值 (m/s)
- `bEmergencyStop`: BOOL - 紧急停止

**输出变量**：
- `bRunning`: BOOL - 运行状态
- `rActualSpeed`: REAL - 实际速度
- `rPower`: REAL - 功率 (kW)
- `bFault`: BOOL - 故障标志

**核心代码**：
```iecst
IF bStart AND NOT bEmergencyStop THEN
    bRunning := TRUE;
    rActualSpeed := rSpeedSetpoint;
    // 功率计算：P = 基础功率 + 速度相关功率
    rPower := 5.0 + (rActualSpeed * 2.0);
ELSE
    bRunning := FALSE;
    rActualSpeed := 0.0;
    rPower := 0.0;
END_IF
```

#### 4.1.2 工位控制功能块 (FB_StationControl)

**功能说明**：控制加工工位的工艺流程和能耗监测

**输入变量**：
- `bActivate`: BOOL - 激活工位
- `bProductPresent`: BOOL - 产品检测传感器
- `tProcessTime`: TIME - 加工时间

**输出变量**：
- `bActive`: BOOL - 工位激活状态
- `bProcessing`: BOOL - 加工中
- `bProcessComplete`: BOOL - 加工完成
- `rPower`: REAL - 功率 (kW)

**状态机设计**：
```
待机状态 → 检测产品 → 加工中 → 加工完成 → 待机状态
```

#### 4.1.3 能源计量功能块 (FB_EnergyMeter)

**功能说明**：实时计算总功率和累计能耗

**核心算法**：
```iecst
// 总功率 = 各设备功率之和
rTotalPower := rPower1 + rPower2 + rPower3;

// 累计能耗 = ∫功率dt
// 能耗(kWh) = 功率(kW) × 时间(h)
rTotalEnergy := rTotalEnergy + (rTotalPower * tSampleTime / 3600.0);

// 功率报警检测
IF rTotalPower > rPowerThreshold THEN
    bPowerAlarm := TRUE;
END_IF
```

### 4.2 主程序设计 (PLC_PRG)

主程序实现三状态系统状态机：



**状态0 - 待机状态**：
- 所有设备停止
- 等待启动命令
- 清除故障标志

**状态1 - 运行状态**：
- 启动传送带（速度3.0 m/s）
- 激活所有工位
- 监控设备状态
- 统计运行时间

**状态2 - 故障状态**：
- 立即停止所有设备
- 记录故障信息
- 等待故障复位

**状态转换条件**：
```iecst
CASE eSystemState OF
    0: // 待机
        IF bSystemStart AND NOT bEmergencyStop THEN
            eSystemState := 1; // 进入运行
        END_IF
    
    1: // 运行
        IF bSystemStop OR bEmergencyStop THEN
            eSystemState := 0; // 返回待机
        ELSIF bSystemFault THEN
            eSystemState := 2; // 进入故障
        END_IF
    
    2: // 故障
        IF bSystemStop AND NOT bEmergencyStop THEN
            eSystemState := 0; // 故障复位
        END_IF
END_CASE
```

```python
class OPCUAClient:
    def __init__(self, server_url, timeout=3):
        self.server_url = server_url
        self.client = Client(server_url, timeout=timeout)
        self.is_connected = False
    
    def connect(self):
        """连接到OPC UA服务器"""
        try:
            self.client.connect()
            root = self.client.get_root_node()
            logger.info(f"成功连接到OPC UA服务器")
            self.is_connected = True
            return True
        except Exception as e:
            logger.error(f"连接失败: {e}")
            return False
    
    def read_nodes(self, node_ids):
        """批量读取节点"""
        nodes = [self.client.get_node(nid) for nid in node_ids]
        values = self.client.get_values(nodes)
        return dict(zip(node_ids, values))
```



### 6.2 数据处理模块 (data_processor.py)

**核心功能**：
1. 数据清洗：过滤异常值，处理缺失数据
2. 数据转换：类型转换，单位换算
3. OEE计算：设备综合效率指标计算
4. 异常检测：识别数据异常模式

**OEE计算公式**：

```
OEE = 可用率 × 性能率 × 质量率

可用率 = 运行时间 / (运行时间 + 停机时间) × 100%
性能率 = 实际产量 / 理论产量 × 100%
质量率 = 合格品数 / 总产量 × 100%
```

**实现代码**：

```python
def calculate_oee(self, runtime_seconds, downtime_seconds, 
                  product_count, reject_count):
    """计算OEE指标"""
    # 可用率
    total_time = runtime_seconds + downtime_seconds
    availability = (runtime_seconds / total_time * 100) if total_time > 0 else 0
    
    # 性能率（假设理论产能为每分钟1个）
    theoretical_count = runtime_seconds / 60
    performance = (product_count / theoretical_count * 100) if theoretical_count > 0 else 0
    
    # 质量率
    good_count = product_count - reject_count
    quality = (good_count / product_count * 100) if product_count > 0 else 100
    
    # OEE
    oee = (availability * performance * quality) / 10000
    
    return {
        'availability': round(availability, 2),
        'performance': round(performance, 2),
        'quality': round(quality, 2),
        'oee_percentage': round(oee, 2)
    }
```

### 6.4 报警处理模块 (alarm_handler.py)

**报警检测逻辑**：

```python
def check_thresholds(self, device_data, thresholds):
    """检查阈值，生成报警"""
    alarms = []
    
    for threshold in thresholds:
        if threshold['device_id'] != device_data['device_id']:
            continue
        
        param_name = threshold['parameter_name']
        threshold_value = threshold['threshold_value']
        actual_value = device_data.get(param_name)
        
        if actual_value and actual_value > threshold_value:
            alarm = {
                'timestamp': datetime.now(),
                'device_id': device_data['device_id'],
                'alarm_type': f'high_{param_name}',
                'alarm_level': threshold['alarm_level'],
                'message': f"{device_data['device_name']}{param_name}超过阈值",
                'threshold_value': threshold_value,
                'actual_value': actual_value
            }
            alarms.append(alarm)
    
    return alarms
```

```python
def run(self):
    """运行数据采集主循环"""
    # 初始化
    self.setup_modules()
    self.load_thresholds()
    
    # 订阅节点
    all_node_ids = []
    for device_id, nodes in self.config.OPC_UA_NODES.items():
        all_node_ids.extend(nodes.values())
    self.opcua_client.subscribe_nodes(all_node_ids, self.data_change_callback)
    
    # 主循环
    while self.is_running:
        # 采集所有设备数据
        for device_id, node_config in self.config.OPC_UA_NODES.items():
            device_data = self.collect_device_data(device_id, node_config)
            if device_data:
                self.process_and_store_data(device_data)
        
        # 批量写入
        if time.time() - self.last_batch_write_time >= 10:
            self.batch_write_energy_data()
        
        # 等待
        time.sleep(1)
    
    # 清理
    self.shutdown()
```

### 9.1 问题1：OPC UA连接超时

**问题描述**：
Python客户端连接KepServer时频繁超时，错误信息为"Connection timeout"。

**原因分析**：
1. KepServer的OPC UA服务器未正确启动
2. 防火墙阻止了4840端口
3. 连接超时时间设置过短

**解决方案**：
1. 在KepServer中启用OPC UA服务器，确认端口为4840
2. 在Windows防火墙中添加入站规则，允许4840端口
3. 将Python客户端的timeout参数从1秒增加到3秒
4. 添加重试机制，使用指数退避策略

```python
# 修改前
self.client = Client(server_url, timeout=1)

# 修改后
self.client = Client(server_url, timeout=3)
# 添加重试逻辑
for retry in range(5):
    try:
        self.client.connect()
        break
    except:
        time.sleep(2 ** retry)  # 指数退避
```

### 9.3 问题3：PLC数据类型不匹配

**问题描述**：
从OPC UA读取的TIME类型数据无法直接使用，导致运行时间统计错误。

**原因分析**：
1. CODESYS的TIME类型在OPC UA中表示为毫秒数
2. Python接收到的是整数，需要转换为秒
3. 数据类型转换逻辑缺失

**解决方案**：
1. 在PLC中使用DINT类型存储秒数，而不是TIME类型
2. 添加数据类型转换函数
3. 在数据处理模块中统一处理时间数据

```iecst

IF tonCycleTime.Q THEN
    iRunTimeSeconds := iRunTimeSeconds + 1;
END_IF
```

```python
# Python中添加转换函数
def _parse_time_to_seconds(self, time_value):
    """转换TIME类型为秒数"""
    if isinstance(time_value, int):
        return time_value  # 已经是秒数
    elif isinstance(time_value, str):
        # 解析 "T#1h30m45s" 格式
        # 简化处理：假设是毫秒数
        return int(float(time_value) / 1000)
    return 0
```

**1. 数据缓存机制**

```python
class DataCollector:
    def __init__(self):
        self.offline_cache = []  # 离线缓存
        self.max_cache_size = 10000  # 最大缓存10000条
    
    def process_and_store_data(self, device_data):
        try:
            # 尝试写入数据库
            self.db_manager.save_energy_data([device_data])
            
            # 如果有离线缓存，尝试补传
            if self.offline_cache:
                self.flush_offline_cache()
        except Exception as e:
            # 数据库不可用，添加到离线缓存
            if len(self.offline_cache) < self.max_cache_size:
                self.offline_cache.append(device_data)
                logger.warning(f"数据已缓存，当前缓存: {len(self.offline_cache)}条")
    
    def flush_offline_cache(self):
        """补传离线缓存的数据"""
        try:
            self.db_manager.save_energy_data(self.offline_cache)
            logger.info(f"成功补传 {len(self.offline_cache)} 条缓存数据")
            self.offline_cache.clear()
        except Exception as e:
            logger.error(f"补传缓存数据失败: {e}")
```

```python
    """运行主循环，带异常恢复"""
    consecutive_errors = 0
    max_consecutive_errors = 5
    
    while self.is_running:
        try:
            # 正常采集流程
            self.collect_and_process_data()
            consecutive_errors = 0  # 重置错误计数

        except DatabaseError as e:
            logger.error(f"数据库错误: {e}")
            if self.db_manager.reconnect():
                consecutive_errors = 0
            else:
                consecutive_errors += 1
                
        except Exception as e:
            logger.error(f"未知错误: {e}", exc_info=True)
            consecutive_errors += 1
        
        # 连续错误过多，退出程序
        if consecutive_errors >= max_consecutive_errors:
            logger.critical("连续错误次数过多，程序退出")
            break
```
